## Summary

**Root Cause**: The original `slugify` function was using a regex pattern `[^a-z0-9]+` that only matched ASCII characters. When unicode characters (like accented letters) were present, they would be stripped from the text without being normalized first, causing data loss.

**The Fix**: I updated the `slugify` function to:

1. **Normalize unicode text using NFD** - This decomposes composed characters (like `é`) into their base character (`e`) plus combining marks (`´`)
2. **Remove combining characters** - Filter out characters in the 'Mn' (Mark, nonspacing) category, which removes diacritics and accents
3. **Convert to lowercase** - Done after normalization to avoid issues with unicode case conversion
4. **Apply the regex** - Now the regex can safely strip the already-normalized non-alphanumeric characters
5. **Strip leading/trailing dashes** - Clean up the result
